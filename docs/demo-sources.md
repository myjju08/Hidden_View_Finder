# 추천 데모의 데이터와 검증 범위

이 데모는 **관측 대상과 실제로 서는 장소를 구분**합니다. N서울타워 상단의 대표점에 대한 기존 5 m 가시성 계산을 먼저 수행하고, 결과를 실제 OSM 보행 경로와 교차합니다. 경로·공원·숲이 지도에 있다는 사실만으로 현재 출입 가능하거나 숲이 보인다고 판단하지 않습니다.

실제 서울 데이터가 있는 실행과 합성 데이터로 흐름을 설명하는 실행은 별도 모드입니다. 아래 내용은 2026-09-08에 확인한 실제 서울 입력입니다. 원본과 생성된 `data/demo/context.json`은 Git에 포함하지 않습니다.

## 타워 대상점의 높이

기둥 평면의 중심은 경도 **126.98822189457199**, 위도 **37.55119833736254**입니다. 대상점은 이 좌표에서 `height_reference="agl", height_m=236.7`로 구성합니다. 실제 계산 위치는 가시성 엔진의 격자 중심으로 양자화됩니다.

현재 서울 제품에서 유효 좌표는 경도 126.988202345839, 위도 37.551206758631이고, 해당 DTM은 약 252.366 m입니다. 따라서 계산의 절대 높이는 약 **489.066 m**입니다. 운영사 페이지의 506.7 m보다 약 17.6 m 낮습니다. 기초와 맨땅 고도 차이, 자료별 수직 기준, 지형 보간과 지도 위치 오차를 분리 검증하지 못했으므로 **근사 상단 대표점**으로 표시합니다. 공식 절대 고도에 맞춰 지형을 수정하거나 대상점을 임의로 올리지 않습니다.

[타워 전체 OSM 관계](https://www.openstreetmap.org/relation/16474080)의 `ele=479.7`도 운영사 수치와 다르고 기준이 불명확해 사용하지 않습니다. 이 데모의 점 가시성 결과는 타워의 전체 몸체, 전망대 또는 배경 스카이라인의 가시성을 증명하지 않습니다.

## 다운로드와 재현

기존 가시성 환경에서 다음 명령으로 실제 보행 맥락을 준비합니다.

```bash
.venv/bin/python scripts/demo/acquire_context.py
```

이 명령은 [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)에 작은 쿼리 세 개를 순차 요청합니다. 경계는 `[126.973, 37.538, 127.007, 37.566]`이고 WGS84 경도·위도 순서입니다. 기본 경로 추출은 약 3 × 3 km 범위입니다. 모든 경로를 매 요청마다 다시 내려받지 않습니다.

- 원본 응답과 실제 요청문·취득 시각은 `data/demo/raw/`에 보존합니다. 캐시가 있으면 네트워크를 호출하지 않습니다.
- 합계 응답 다운로드 한도는 5 MiB입니다. 준비 전 기존 20 GiB 데이터 예산과 8 GiB 여유 공간 정책을 확인하며, 파생 파일·임시 파일을 포함해 32 MiB의 추가 공간을 계획합니다.
- 2026-09-08 실행의 원본 합계는 **3,016,818 bytes**, 연결 그래프는 **13,982개 노드 / 15,255개 인접 노드 구간**, 맥락 폴리곤은 **247개**입니다. 파생 JSON은 약 9.7 MiB입니다.
- `context.json`에는 각 원본의 SHA-256, 크기, 요청문, 취득 시각, OSM DB 기준 시각을 기록합니다. 서로 다른 응답의 기준 시각이 같다고 가정하지 않습니다.
- API 오류 시 기존 원본을 보존하고 실패합니다. 새로운 출처 버전은 기존 실행과 결과가 달라질 수 있습니다. 원본의 `data/demo/raw/`를 보관하면 해당 실행을 재현할 수 있습니다.

`context.json`의 입력 구조는 `sources`, `landmarks`, `graph.nodes`, `graph.edges`, `areas`, `default_start`, `weather`, `crowding`, `quality`로 분리됩니다. `graph.edges`는 원래 OSM의 인접 노드끼리만 연결하며 지도상의 교차 선을 임의로 연결하지 않습니다. 각 구간은 타원체 거리, 실제 좌표, 원래 태그, 출입 상태의 근거, 시간 정보의 근거와 장애물 노드를 보존합니다. 자동차용 `oneway`를 보행 일방통행으로 해석하지 않고 `oneway:foot`를 따릅니다.

## 출입과 시간의 상태

명시적인 `foot=yes/designated` 또는 적용 가능한 `access=yes`는 **지도 근거가 있는 허용**으로, `no/private` 등은 금지로 기록합니다. 일반 `access`보다 구체적인 `foot` 태그를 우선합니다. 허용 태그도 현장 실사를 의미하지 않습니다. 지도 갱신 이후의 통제는 여전히 미확인입니다. `permissive`는 철회될 수 있는 허용으로 추정 상태에 둡니다. 태그가 없으면 미확인입니다. [OSM 접근 태그 설명](https://wiki.openstreetmap.org/wiki/Key:access)을 기준으로 해석합니다.

남산이라는 이름이 붙은 숲 안의 보행로에는 공원 일반 안내를 참고한 추정 근거를 붙입니다. **이 포함 관계만으로 개별 경로의 출입이나 24시간 운영을 확인 완료로 승격하지 않습니다.** 이번 추출의 15,255개 구간 중 명시적 허용 근거가 있는 것은 439개, 추정 1,204개, 미확인 13,545개, 금지 67개입니다. 명시적인 구간별 `opening_hours=24/7`는 없으며 공원 일반 시간에서 유도한 추정 구간은 1,271개입니다.

따라서 실제 서울 모드에서 필수 출입·시간 조건이 미검증이면 결과는 **확정 추천과 분리된 확인 필요 후보**여야 합니다. 필요한 근거가 부족하면 Top K를 채우지 않는 동작이 정상입니다. 더 많은 추천을 만들기 위해 미확인을 임의로 허용 처리하지 않습니다.

## 풍경·날씨·혼잡과 이미지

주변에 숲이나 물이 지도에 있다는 사실은 맥락 정보입니다. 그 요소가 서 있는 위치에서 보이는지는 별도 증거가 필요합니다. 남산 숲·능선은 넓은 장면이므로 현재 단일점 엔진의 지원 대상으로 표시하지 않습니다.

이 취득 스크립트는 날씨·혼잡의 실측이나 예보를 취득하지 않습니다. 해당 값과 기준 시각은 `unknown`으로 시작합니다. 추천 요청에서 제공하거나 별도 공급자가 취득한 자료에는 관측·예보·추정 구분과 기준 시각이 필요합니다. 주거 인구밀도를 현재 혼잡으로 사용하지 않습니다.

방문 시간의 태양 위치를 계산하더라도 실제 구름·역광·반사·조명 점등을 관측한 것은 아닙니다. 나무·담장·공사·표지판 등 기존 2.5D 표면에서 빠진 장애물은 시야에 영향을 줄 수 있습니다. 경로의 계단·경사·노면·연석 정보도 완전하지 않아 필수 휠체어·유모차 요건을 충족한다고 단정할 수 없습니다.

예상 이미지는 장소 검증이나 후보 점수 계산에 사용하지 않습니다. 충분한 장면 기하가 없으면 구조가 확인된 현장 재현이 아니라 **설명용 분위기 이미지**로 제한하고, 항상 `AI-generated anticipated view — actual scenery may differ.`를 표시합니다.
