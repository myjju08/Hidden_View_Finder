# 실제 서울 실행·벤치마크

**2026-09-07 개발 환경에서 중앙 서울 5 km / 5 m 질의의 캐시 없는 중앙값은 0.544초, p95는 0.599초였습니다.** 실제 지형과 추정 건물 높이를 사용한 결과이며, 현장 가시성 정확도나 다른 컴퓨터의 속도를 보장하는 수치가 아닙니다.

## 측정 조건

| 항목 | 실제 조건 |
| --- | --- |
| 계산 범위 | 중앙 서울 11.5 × 11.5 km, EPSG:5186, 2,300 × 2,300셀, 5 m |
| CPU | AMD Ryzen Threadripper PRO 3955WX, 물리 16코어 / 논리 32코어, affinity 32 |
| RAM | 측정 당시 호스트 가용 RAM 약 233 GiB |
| OS·저장장치 | Linux 6.8 / glibc 2.39, overlay 파일시스템; 물리 저장장치 종류 미확인 |
| 주요 버전 | Python 3.12.14, GDAL 3.8.4, NumPy 2.5.2, SciPy 1.18.1 |
| 병렬·캐시 설정 | `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, GDAL block cache 64 MiB, 결과 RAM cache 128 MiB, 결과 disk cache 0 bytes |
| 목표점 | 시드 1729, 서로 다른 위치의 명시적 120 m AGL 가상 목표점 5개 |
| 관측자·곡률 | 지면 위 눈높이 1.7 m, 곡률 계수 6/7 |

반경별로 **결과 캐시 없는 계산 30회 + 동일 결과 캐시 조회 30회**를 분리해 측정했습니다. 데이터 블록을 먼저 읽은 **warm filesystem/data** 조건이며 cold-disk 측정이 아닙니다. OS 캐시를 강제로 비우지 않았습니다. 5 km에서는 목표점 1개의 입력 범위가 불완전해 제외했고, 남은 4개 위치로 30회를 측정했습니다. GPU·JIT는 사용하지 않았습니다.

5 km 설계 목표인 중앙값 ≤1초 / p95 ≤3초를 이 환경에서 충족했습니다. 5 m 제품을 확대해 2 m 성능·정확도로 제시하지 않았습니다. 측정한 90회 계산과 90회 캐시 조회는 [180회 CSV](../reports/seoul-real-benchmark/runs.csv)에, 환경·버전·제외 사유·표본 설정은 [benchmark.json](../reports/seoul-real-benchmark/benchmark.json)에 있습니다. 결과 캐시 조회 시간을 새로운 목표점 계산 시간으로 사용하지 않습니다.

5 km의 단계별 중앙값은 읽기·검사 **0.33595 s**, native viewshed **0.10522 s**, 마스킹·결과 구성 **0.09010 s**였습니다. 단계별 중앙값의 합은 전체 중앙값과 같을 필요가 없습니다. 가장 큰 비용은 준비 래스터의 읽기·검사였으며 정확성 검사를 줄여 시간을 맞추지 않았습니다.

이 단계들은 질의 때 반복하지 않습니다. 최초 전체 지형 작업은 약 1,115초 진행 후 외부 SIGTERM으로 중단되었습니다. 이후 같은 타일의 반복 삼각분할을 줄이고 지형 저장·표고점 검증을 재개하도록 개선했습니다. 표의 성공 시간에 앞선 실패 시간을 숨겨 합치지 않았습니다. 개선 실행의 kernel 최대 RSS는 약 204 MiB, 장애물 준비는 약 187 MiB였습니다.

준비 제품과 인덱스 크기는 48,710,184 bytes였습니다. 작업 완료 당시 원본·중간 파일을 포함한 로컬 데이터는 약 0.659 GiB, 파일시스템 여유는 약 40.72 GiB였습니다. 이 실제 데이터 작업에서는 기존 환경을 사용했으며 최초 환경 설치 비용은 위 전처리 시간에 포함하지 않습니다.

## 검증과 해석 범위

자동 테스트는 **173개 통과, 실패·오류·skip 0**이고 `pip check`도 통과했습니다. 당시 실행 요약은 [test_summary.json](../reports/test_summary.json)에 있습니다. 평지·능선·건물 벽·높이 차이·건물 위 목표점·아래 지붕 목표점 거부·곡률·상호성·셀 모서리 장애물·누락 입력·좌표계·캐시·예산·재개·정리 동작을 검사했습니다.

별도 지형 검증은 후보 표고점 2,881개 중 시드 0으로 제한 표집한 500개를 사용했습니다. 보간이 지원되는 492개의 RMSE는 **2.566 m**, bias는 **−0.195 m**이며 8개는 지원 부족으로 기록했습니다. 이 표본 오차는 전 지역의 확률 가중 정확도나 5 m 격자 정확도 보장이 아닙니다.

광화문 부근 지면 위 100 m의 **가상 목표점**을 별도로 지정한 5 km 검증에서 가시·차폐를 균등 표집한 100셀 중 native/reference 불일치는 **false-visible 3개, false-blocked 0개**였습니다. 2개는 건물 기둥 구간, 1개는 지형 기둥 구간에서 발생했습니다. 같은 기하를 쓰는 sparse/reference는 100/100, reference 상호성은 12/12 일치했습니다. GDAL의 보간 지평선과 상수 높이 셀 기둥 reference는 표면 해석이 다르므로 같다고 강제하지 않았습니다. 균등 표집 비율을 전체 정확도로 해석하거나 현장 실측 정답으로 삼지 않습니다.

NoData가 남은 미사용 사각형 모서리 때문에 정상 원형 질의를 과도하게 거부하는 문제는 **GDAL 3.8.4 / GVM_Edge / 북향 정사각 격자**의 실제 의존 경로를 검토해 해결했습니다. 45가지 시나리오에서 반경 밖 높이를 바꾼 180회 비교의 내부 결과 차이는 0이었습니다. [소스 검토·실험 설명](../reports/gdal-radial-dependencies/probe.md)과 [기계 판독 결과](../reports/gdal-radial-dependencies/probe.json)를 보존합니다. 이는 이 버전·방식의 계산 의존 영역 검증이며 물리적 가시성의 보증이 아닙니다. 다른 버전·방식은 사각형 전수 검사로 돌아갑니다.

실제 필요한 반경과 한 셀 여유 안에 누락이 있으면 계속 거부합니다. 같은 광화문 점의 5.5 km 질의는 필요한 불완전 셀 1,468개 때문에, 10 km는 준비 범위 초과로 거부되었습니다. 원본 NoData는 채우지 않았습니다.

모든 실제 결과는 **APPROXIMATE**입니다. 추정 높이·누락 건물·최고 지형 기반 지붕·보수적 footprint rasterization은 양방향 가시성 오차를 만들 수 있습니다. 결과는 한 점의 기하학적 가시성만 뜻하며 경관의 매력, 건물 전체의 가시성, 공공 출입 가능성은 뜻하지 않습니다. 수목·간판·발코니·대기 상태 등도 포함하지 않습니다. 입력 출처와 제약은 [데이터 문서](data-sources.md), 재현 명령은 [메인 README](../README.md)에 있습니다.
